Code and notebooks

The calculations ran in Google Colab notebooks. The notebooks are published without outputs; the Python modules they paste into their cells are published as plain files. You can re-run the whole study on Colab, or only re-check the published numbers on your own computer in a few seconds.

The Colab and GitHub buttons use the repository name set in js/config.js, which still holds a placeholder. Set repo there (see README.md) and the buttons work.

How to run on Colab

  1. Click Open in Colab for the CPU notebook. (If the button is dashed, js/config.js still holds the placeholder repository name; download the notebook and upload it to Colab instead.)
  2. Use the default CPU runtime. For the GPU notebook choose Runtime > Change runtime type > GPU; a T4 is enough, an L4 or A100 reaches further down the list of calculations.
  3. Choose Runtime > Run all. The first cell mounts Google Drive and shows a popup: click Allow at once. The notebook retries the mount up to three times.
  4. Wait. Every calculation is appended to a CSV file in the Drive folder MyDrive/skala-b1-v5 as soon as it finishes, so a disconnect loses nothing.
  5. If the runtime stops or a calculation was refused by the deadline queue, choose Run all again: finished calculations are skipped and the notebook continues where it stopped.
  6. Run the GPU notebook after the CPU notebook: its last phases read the coupled-cluster results from the same Drive folder. At the end the folder holds the CSV files that this site publishes in data / results.
  7. To fetch the folder, run B1v5_collect_zip and download the zip.

Expected times. CPU notebook: about 28 minutes for the core list and up to 50 minutes with the tail. GPU notebook: about 50 minutes on a T4 (it completes the core list there). Diagnostic 1: about 25 minutes. Diagnostic 2: 20 to 30 minutes. Collector: about a minute. The times are estimates for a free Colab runtime and vary with the hardware you are given.

Outputs. One CSV per phase (phase03_ccsdt.csv, phase11_dft.csv, ...), geometries, check_report.csv and check_report.md, findings_outcome.csv, tables, figures and RUN_SUMMARY.md. The published copies are in data.

The deadline queue. Both one-hour notebooks use one ordered list of calculations. Before each calculation the notebook asks whether it can finish before minute 50 (elapsed time plus 1.5 times the running mean time of that kind of calculation must stay below 50 minutes, and the phase must stay inside its own cap). A calculation that does not fit is not started; it is listed as "not run (time)" in RUN_SUMMARY.md and queue_not_run.csv. All of them were completed in a later session of the study.

SCF rescue ladder

When a self-consistent-field calculation does not converge, the notebooks try these steps in order and stop at the first that converges. The energy table records which attempt gave each energy (column attempt).

  1. Default start (the usual initial guess).
  2. Warm start from the density of a neighbouring point or a related calculation.
  3. Fresh start with a different initial guess.
  4. Level shift.
  5. Start from the PBE density, with a level shift of 0.3 and up to 300 cycles.
  6. Density fitting, with a level shift of 0.5 and up to 400 cycles.

The Cl⁻ + CH₃Cl transition state with Skala-1.1 converged only on the last rung. Diagnostic 1 shows that density fitting changes that energy by about 0.05 kcal/mol, and the symmetric-stretch demo shows it with its neighbours. A barrier never mixes density-fitted and unfitted energies (check I14).

Quirks to know

  • Drive first. The mount popup is the only click the notebooks need. If you are late, the mount fails and is retried; if all three attempts fail, the notebook works in a local folder, and the last cell zips and downloads the results instead of releasing the runtime.
  • The last cell releases the runtime to stop billing, unless Drive was not mounted. Set AUTO_DISCONNECT = False in the settings cell to keep it.
  • Failed points. Set RETRY_FAILED = True to retry calculations that failed, and FORCE_RERUN = True to recompute finished ones.
  • Stand-in mode. STANDIN = True runs the whole notebook on a plain CPU with cheap functionals in tiny basis sets, to test the machinery. Its numbers are not results.
  • Extension items. EXTENSION flags run extra reactions (F⁻ + CH₃Cl and OH⁻ + CH₃F) in a session of their own. They are not part of the paper.
  • Skala without D3 is the same SCF with the stored D3 energy removed; it is not a second calculation.
  • Geometries are not recomputed. They come from the geometry pack (below); REBUILD_GEOMS = True rebuilds them, which takes hours.

Re-check the numbers on your computer

The automatic check that the notebooks run at the end is a plain Python module. code/recheck_numbers.py runs it again on the published calculation records and compares the result with the published check_report.csv. Needs Python 3 and numpy.

git clone <the repository> && cd <the repository>
python code/recheck_numbers.py

Expected output:

items: 139 (published report: 139)
counts: PASS 54, WARN 14, FAIL 5, NOT RUN 40, N/A 4, INFO 22
check_report.csv: identical to the published file

The result of the check, with every warning and failure explained, is on the Checks page.

Rebuild the figures

The figures, the tables and their captions are drawn by a Python script that reads only the CSV, JSON and xyz files of this repository (data/). It needs Python 3, numpy, pandas, matplotlib and Pillow (requirements.txt), takes less than a minute, and writes to a new folder, so the published files are not overwritten.

pip install -r requirements.txt
python figures/code/build_figures.py
python figures/code/compare_with_published.py

The second script compares the rebuilt data files, tables and PNG pixels with the published ones and prints all agree. Files and details: figures/code/README.md.
